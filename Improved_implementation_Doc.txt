A better algorithm for Lcubs can be done using dynamic programming and memoisation

We can cut up the string into 3 subsequences using the ranges p and q 
x1 = string[:p]
x2 = string[p:q]
x3 = string[q:]

With the 3 subsequences we obtained we can get the longest common subsequence between them

if we get a common subsequence we record it in a memoisation table so that it doesn't get 
recomputed again.

Then we iterate through all the possible pairs of p and q in order to find all the common subsequences

Improvements upon the base dp memoisation implementation: 

Pruning - removing letters that appear less than 3 times/ prune letters so that they only exist in multiples of 3

Remove uneccessary state searches 

Stopping once we have found a global max 
This global max is defined by the sum of all letters greater than 3 divided by 3

Strategically assigning our ps and qs. We can assign specific values to p and q in order to find 
cubic sequences faster. These values can be assigned so that they are one after the indexes of a letter (since slicing is exclusive we do one after so that it includes the letter) 
that occur 3 or more times. This way we can encompass ranges where all three subsequences end with a given letter and also start one index after the given letter
